# Changelog

A release is cut by bumping `version` in `package.json` on main. The section here for that version becomes the release notes, so every version needs one.

## 2.2.0 - 2026-11-17

Look before you send, and a dated answer to "does this broker's form still work?". Read **Limits** before you rely on either: both are narrower than the roadmap hoped.

### New

- **`aidr scan`** (F2): searches each broker that can be searched, for each person, and records found, not found or could not tell, with the listing URL and a private screenshot. It submits nothing and sends no email. It honours `--only` and `--skip`, and exits 2 when every search came back "could not tell".
- **`aidr run --found-only`** (F2): submits only where the latest scan found you.
  - A scan result counts only if it was made with the same search the run would do now, and is no older than `scan.maxAgeDays` (default 30).
  - Only a broker whose search step has been validated can be skipped on "not found". Everything else (could not tell, stale, never scanned, cannot be searched, and the email and generic passes) follows `scan.unknown`: `submit` (the default) or `skip`.
  - The run prints, per person, how many brokers it submits or skips and why.
- **"Never seen" is no longer "removed"** (F2): `aidr verify` reports a broker where no listing was ever seen apart from one where a listing was seen and is now gone. Only the second counts as a removal in the score and the report. A scan that finds you counts as listed, and a later sighting overrides an earlier "absent".
- **A weekly broker health check** (F3): a scheduled job loads each explicit broker's opt-out page with a plain browser and checks that the page answers and that the form fields the tool relies on are still there. It never types, clicks or submits, and uses no personal data.
  - Each broker gets `ok`, `drifted`, `blocked`, `dead` or `error` with a date. `STATUS.md` is generated from that, and the README shows the count.
  - One issue is opened per drifted broker after two checks in a row, and closed when the broker is `ok` again.
  - `aidr doctor --brokers` runs the same check from your machine.
- **USPhonebook can be searched**, validated against the live site in both directions.

### Changed

- **A page must look like a results page before "not listed" is believed.** It has to be on the same site as the search and name the person searched for. Otherwise the answer is "could not tell". `aidr verify` may now say "could not tell" where it used to say clear.
- **Radaris and PeekYou are removed.** Both domains were transferred to another company by court order, and every address on radaris.com now shows the same notice, which the tool had been reading as "not listed" for everyone. `brokers.js` lists 48 explicit brokers.
- `STATUS.md` is generated by `scripts/generate-status.js`. Every broker used to be marked `untested`.
- `aidr verify` and `aidr scan` refuse flags that mean nothing to them (`--pollute`, `--resume`, `--solve-captchas`, `--snapshot`, `--fields`) where they used to ignore them.
- The dashboard returns only the host of a scan's listing URL, since the path carries your name.

### Limits

- **Few brokers can be searched.** The roadmap aimed for about 20. There are six (Spokeo, WhitePages, FastPeopleSearch, MyLife, Nuwber, USPhonebook), and only USPhonebook's search has been validated, because the other sites refuse a plain browser and the tool does not get around bot checks. For most brokers a scan says "could not tell" or cannot search at all, so with the default `scan.unknown: submit`, `--found-only` changes little today.
- **The first health check could not confirm most forms.** From a home connection on 2026-11-17, of 44 opt-out pages: 12 `ok` (4 automated forms; the other 8 are manual brokers, where only "the page answers" is checked), 13 `drifted`, 18 `blocked` and 1 `error`. `drifted` means the form the tool expects is not visible on the page; it is a prompt to look, not proof the opt-out fails.
- The health check looks at the shape of the form. It cannot tell you whether a submission deletes anything; `aidr verify` is the check for that.
- The scheduled job has not yet run on GitHub. Its first runs are the real test of the workflow file.

### How it was checked

Written test-first. An independent review of the release branch found 1 P1, 9 P2 and 7 P3 issues before release; all are fixed, each with a test that failed first. A mutation check planted 24 bugs in the new rules: 21 were caught, 1 could not change behaviour, and the 2 that slipped through now have tests.

## 2.1.0 - 2026-11-17

California's one-request deletion platform, broker lists that are current again, a cap on CAPTCHA spend, and a way to see what would be sent before it is sent. An existing install behaves as before until you use the new commands or settings, apart from the two items under **Changed**.

### New

- **`aidr drop`** (F1), for California residents. California's Delete Request and Opt-out Platform (DROP) lets one request cover every data broker on the state registry. The state verifies who you are, so the tool cannot file it for you. What it does:
  - `aidr drop` explains the platform, links to it and shows where your request stands. `aidr drop --done` records that you filed it (`--on YYYY-MM-DD` for another day, `--person "First Last"` when several California residents are configured, `--clear` to undo).
  - Once a request is recorded, the generic pass skips the brokers on the California registry for that person and says how many. Against the registry on the day of this release that was 383 of the 519 bundled generic brokers. The explicit people-search brokers still run. `drop.alsoSubmit: true` keeps sending to everyone.
  - Brokers have up to 90 days: 45 to pick a request up and 45 to delete (Cal. Civ. Code 1798.99.86). After that, `aidr complaints` can draft a complaint to the California privacy agency, but only for a registry broker that `aidr verify` found still listing you after the deadline. It never drafts one from the age of a request.
  - Run `aidr update-brokers` once so the tool knows the registry.
- **`aidr preview --fields`** (Q4): for each broker, which of your details would go into which field, what its search URL and opt-out URL carry, and a closing table with totals. Names of details only; `--show-values` prints the values on your terminal. With `--fields`, nothing is typed into the generic brokers' forms. The audit report of a real run now lists the details typed for each broker, names only.
- **`capsolver.maxSolvesPerRun`** (Q2): a ceiling on paid CAPTCHA solves in one run, shared by every person and both passes. When it is reached, the remaining CAPTCHA brokers are left for `aidr captchas`. The run summary shows the solves used and the spend, read from your CapSolver balance before and after.
- **Registries per broker** (Q3): each registry row records which state registries list it.

### Changed

- **`aidr update-brokers` reads California's current registry** (Q3). The address it used before now answers 403, so the command had been getting nothing from California. It now prints a count or a failure per registry, keeps the earlier rows of a registry that fails, and exits 1 only when every registry failed (it always exited 0 before). Vermont's export stopped serving a file and is skipped with one line; set `VT_REGISTRY_URL` if you have a working export. Texas and Oregon publish no export, so they are not read.
- `data/feeds-brokers.json` is now an object (`brokers`, `registryHosts`, `registries`, `updatedAt`). A file in the old array shape is still read.
- One accurate `CalPrivacy DROP` manual entry replaces two stale ones and is shown only to California residents, so `brokers.js` lists 50 explicit brokers.

### Fixed

- The README, `STATUS.md` and `brokers.js` said DROP was "not yet live". It opened to consumers on 2026-01-01 and brokers have had to act on requests since 2026-08-01.
- The README described the old Attorney General export (2020 to 2023) as the current California registry.

### How it was checked

Written test-first. An independent review of the release branch found 2 P1, 4 P2 and 7 P3 issues before release; all are fixed, each with a test that failed first. A mutation check then planted 22 chosen bugs in the new rules, all of which the tests caught, and about 27 more: 7 slipped through and now have tests.

## 2.0.1 - 2026-10-30

A prebuilt Docker image, so a NAS no longer has to build one. The tool itself is the same as 2.0.0.

### New

- **A prebuilt multi-arch image on GitHub Container Registry with every release** ([#8](https://github.com/stephenlthorn/auto-identity-remove/issues/8)): `ghcr.io/stephenlthorn/auto-identity-remove`, for `linux/amd64` and `linux/arm64`, tagged with the version and `latest`. The release workflow builds it from the release tag and launches Chromium in it before it publishes anything. A Synology DS720+ now pulls it, instead of downloading the source and building a 940 MB Playwright image on a Celeron.

### Docs and compose

- `docs/SYNOLOGY.md` and the README's Docker section lead with the prebuilt image: `docker pull`, then a plain `docker run`. The DSM Task Scheduler line is a plain `docker run --rm ...` that needs no compose file and no source on the NAS. Building from source is a short alternative.
- `docker-compose.yml` pulls the image by default, and `AIDR_VERSION` pins a release. If you ran `docker compose run` from a checkout and relied on it building the image, build it with `docker compose -f docker-compose.yml -f docker-compose.build.yml build`.

## 2.0.0 - 2026-10-30

A full audit, fix and roadmap pass, written test-first. It is a major version because some behaviour changes for existing installs: read **Upgrading from 1.x** before you update.

### New

- **One home directory** (R0): `AIDR_HOME` holds config, state, logs, reports and history. Docker and Synology need a single mount.
- **Solve CAPTCHAs yourself** (R1, #16): `captcha.manual`, `--solve-captchas` and `aidr captchas`.
- **`--resume` covers the generic pass** (R2): the ~490-broker pass is checkpointed per person and row.
- **Crash-safe run journal** (R3): `logs/run-<ts>.jsonl`, read by `--retry-failed`, `aidr captchas` and the diff when the summary is missing.
- **A scheduler you can see and undo** (R4): `aidr schedule status|install|uninstall`, a `last-run.json` heartbeat and new `aidr doctor` checks. The Windows Task Scheduler reading and the launchctl and systemctl exit codes are not yet verified on live hosts.
- **`aidr config check`** and identity fingerprints on state entries (R5): correcting a zip or email re-runs that person. Existing entries are trusted, so nothing re-runs on upgrade.
- **Retention** (R6): `aidr purge` and `retention.days`.
- **Browser isolation** (R7): a profile per person, a regular Chrome user agent when headless, and `browser.proxy`.
- **Dashboard** (R8): run history, per-person status, generic-broker totals and a CAPTCHA call to action.

### Fixed

Two audit rounds, each with independent same-family auditors and a cross-model review: about 85 findings, then about 45 on the new code. All are fixed or dispositioned. The main themes:

- Outcomes recorded as removals that were not: forms never sent, "try again" confirmation pages, policy pages.
- Wrong person, wrong data in multi-person setups, and email relay bypasses.
- Security: the SSRF guard fails closed, the dashboard closes DNS rebinding, CSRF and path traversal holes, and a one-character passphrase is refused.
- Scheduling and recovery: failed scheduler installs say so, crashed runs exit non-zero, and a dead browser is relaunched.
- Docker recipes now persist what they claim to.
- The old `test/scheduler.test.js` rewrote the real user crontab on every run of the suite. It no longer touches it.

The plan is in `docs/plans/2026-10-29-roadmap.md`. The full account is in PR #20.

### Upgrading from 1.x

- **If you ran the test suite** (`npm test`) from a checkout between 2026-08-13 and 2026-10-29, check `crontab -l`. The old scheduler test replaced your whole crontab with a single test line pointing at a temporary folder. Restore any jobs you had from a backup; `aidr schedule install` puts back the monthly aidr job.
- Node 20 or newer is required (nodemailer 10). CI runs 20, 22 and 24.
- The dashboard requires a username and password, even on localhost. `aidr dashboard` prints generated ones, and `AIDR_PASS=change-me` counts as unset.
- Unknown or misspelled flags exit 2 with a suggestion. For example, `--dryrun` suggests `--dry-run`.
- A run where every broker failed exits 1. So does a run where most sites could not be resolved: that points to a network or DNS problem, not to dead brokers. `aidr schedule status` exits non-zero when the last full run failed or crashed, and says when it could not reach most sites.
- In a headed, interactive run, `captcha.manual: "auto"` waits up to 180 s per CAPTCHA for you to solve it.
- When an email relay is configured, `email.smtp.from` should be a dedicated sender address. Otherwise brokers still see your real mailbox in `From`. `aidr config check` and `aidr doctor` warn about this.
- The Docker image uses `AIDR_HOME=/home/aidr`. The old `/app/config.json` mounts fail with a message naming both paths, so they are not silently ignored.
