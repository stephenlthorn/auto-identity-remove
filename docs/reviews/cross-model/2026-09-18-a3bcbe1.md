### Detail

#### 1. [P1] Runtime-file check misses Docker image leakage of checkpoint data

- **Location:** `test/runtime-files-gitignored.test.js:24`
- **What:** The new coverage verifies only Git ignore rules, while the repository's Docker build uses `COPY . .` and `.dockerignore` does not exclude `state.json.checkpoint` or `state.json.checkpoint.tmp`. Those files contain the broker checkpoint/history associated with the user's PII and can be copied into a built or published image.
- **Trigger:** Run an opt-out pass, then build the documented Docker image from that checkout and push/share the image or its layers.
- **Impact:** A Docker registry or anyone with access to the image can recover the user's broker-related run history, despite the patch's claim that runtime files cannot be committed or shipped.
- **Fix:** Add `state.json.checkpoint` and `state.json.checkpoint.tmp` to `.dockerignore`, and extend the runtime-file test to validate both Git and Docker ignore coverage.
- **Disposition:** **fixed** in this change. Verified before acting, not taken on
  the reviewer's word: with a `COPY . .` build of this context, `state.json` was
  correctly excluded and `state.json.checkpoint` was copied into `/app`. After
  adding both paths to `.dockerignore`, a `--no-cache` rebuild of the same
  context contains no state files at all. The CI step that builds the image and
  greps for PII was missing the checkpoint too, so it is extended here as well;
  the structural parity test in `test/runtime-files-not-shipped.test.js` is the
  hermetic half.
- **Note on measurement:** an intermediate rebuild without `--no-cache` reported
  *every* state file present, including ones the previous build had correctly
  excluded. That was a BuildKit layer-cache artifact, not the code. Any
  `.dockerignore` A/B here must pass `--no-cache` or it measures the cache.
