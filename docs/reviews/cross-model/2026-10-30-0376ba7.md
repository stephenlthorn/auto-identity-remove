### Detail

#### 1. [P2] The default `latest` tag is pulled on every Compose run

- **Location:** `docker-compose.yml:55`
- **What:** Compose always pulls an image tagged `latest`, even under its default `missing` policy ([Docker Compose service reference](https://docs.docker.com/reference/compose-file/services/)). This contradicts the documented claim that later runs use the cached image, and a source build can be replaced when the next run pulls `latest`.
- **Trigger:** Run `docker compose run --rm watcher` with the default `AIDR_VERSION` or with `AIDR_VERSION=latest`; the same applies to scheduled Compose runs.
- **Impact:** Runs can update to a new release without an explicit update, and a temporary GHCR outage can prevent a scheduled run despite a cached image. The documented build-from-source flow can also run the registry image instead of the local build.
- **Fix:** Use an immutable release tag as the default with a missing-only pull policy, or set `pull_policy: never` and document an explicit `docker compose pull` before the first run and each update.
- **Disposition:** not-a-bug: measured on Compose v2.34.0 with the default pull policy. A local image tagged `ghcr.io/stephenlthorn/aidr-pull-probe-nonexistent:latest`, a name that does not exist on GHCR, went straight to container creation under `docker compose run` with no pull attempt (a pull would have failed with not found). A cached `latest` is not re-pulled, so a scheduled run neither updates itself nor depends on GHCR being up, and a local build tagged with the same name is the one that runs. Pinning a release is documented via `AIDR_VERSION`.
