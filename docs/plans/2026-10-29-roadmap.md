# Roadmap - 2026-10-29

Written after the 2026-10-29 audit (five same-family auditors plus the codex cross-model pass, ~85 confirmed
findings, all fixed or dispositioned on `overhaul/2026-10-29`). This is what comes next, in priority order.
Every item ships with tests written first, and nothing here makes the run concurrent: one page at a time is
what keeps a 2 GB NAS at ~250 MB.

## Now (this release)

### R0. One home directory for every runtime file
**Problem.** Config and state can now live outside the app directory (`AIDR_CONFIG_PATH`,
`AIDR_STATE_PATH`), but logs, screenshots, reports and the SERP/exposure/breach history are still
hardcoded under the app directory. In Docker they vanish with the container unless each gets its own mount.
**Shape.** `AIDR_HOME`: when set, config, state, lock, checkpoint, logs, snapshots, reports, complaints and the
history files all default to paths inside it (each specific `AIDR_*_PATH` still wins). Docker and Synology
recipes collapse to one mount. `aidr doctor` prints every resolved path.

### R1. Solve CAPTCHAs yourself (issue #16)
**Problem.** Without a CapSolver key, a CAPTCHA broker is marked `captcha_failed` and the run moves on, so
the browser closes before a person at the keyboard can do anything. #16 asked for exactly this.
**Shape.**
- `captcha.manual` in config: `"auto"` (default), `true`, `false`. Auto means: headed browser, an
  interactive terminal, and either no CapSolver key or CapSolver failed.
- When a CAPTCHA is detected and manual solving applies, bring the page to the front, ring the terminal
  bell, post a desktop notification, and wait (default 3 minutes, `captcha.manualTimeoutSec`) until the
  widget reports a token (`g-recaptcha-response`, `h-captcha-response`, `cf-turnstile-response`) or
  disappears. Then continue with the normal submit and post-submit classification.
- `aidr captchas`: re-runs only the brokers that ended `captcha_failed` (or `manual` because of a CAPTCHA)
  in the most recent run, headed, with manual solving forced on.
- Headless/Docker: say plainly that a display is needed and point at `aidr captchas` on a desktop machine.
**Done when.** A local test page with a fake CAPTCHA widget is solved by a scripted "human" during the
wait and the broker records `success`; a timeout records `captcha_failed` without hanging the run.

### R2. Resume the generic pass
**Problem.** `--resume` only covers the ~50 explicit brokers. A run killed during the ~490-broker generic
pass (most of the wall-clock) starts that pass over.
**Shape.** Checkpoint `{ phase: 'generic', person, index }` as the generic loop advances; `--resume`
skips completed persons and indices. Old checkpoints (a bare broker name) keep working.

### R3. Crash-safe run journal
**Problem.** The run log is written once at the end. A crash, OOM kill or `docker stop` leaves no log, so
`--retry-failed` has nothing to read and the audit trail has a hole.
**Shape.** Append every result to `logs/run-<ts>.jsonl` (0600) as it happens; the end-of-run JSON stays
as the summary. `--retry-failed`, `aidr captchas` and the diff read the journal when the summary is
missing.

### R4. Scheduler you can see and undo
**Problem.** `setup` can install a monthly job but there is no way to check it or remove it, and a broken
job fails silently.
**Shape.** `aidr schedule status|install|uninstall`. Each run writes a small heartbeat
(`last-run.json`: start, end, outcome, counts). `status` shows whether the job exists, when it last ran
and how it ended. `aidr doctor` gains: lock age and holder, job installed and recently run, encrypted
config has a passphrase source for unattended runs.

### R5. `aidr config check` and identity-aware state
**Problem.** Mistakes in config.json surface as odd broker results months later. State is keyed by name
only, so correcting a zip or email leaves the old "done" entries in force for 90 days, and two people with
the same name share entries.
**Shape.** `aidr config check` prints every validation problem, which config file and passphrase source
are in use, and where state lives. State entries gain an identity fingerprint (hash of the normalized
name, zip, email, phone); an entry whose fingerprint does not match the current person counts as never
run. Entries without a fingerprint (all existing state) are trusted, so nothing re-runs on upgrade.

### R6. Retention for PII artifacts
**Problem.** Run logs, audit reports and full-page screenshots accumulate forever, each holding PII.
**Shape.** `aidr purge [--older-than 180d] [--dry-run]` and an optional `retention.days` applied at the
end of each run. Complaints and the audit report of the latest run are never purged automatically.

### R7. Browser isolation and hardening
**Problem.** Cookies and localStorage carry from person A to person B in one profile. Headless Chromium
announces itself as `HeadlessChrome` in its user agent, an easy bot-block. There is no way to route the
browser through a proxy.
**Shape.** One browser profile directory per person. Normalize the headless user agent to the matching
regular Chrome string. Optional `browser.proxy` (`server`, `username`, `password`) passed to Playwright.

### R8. Dashboard: history and people
**Problem.** The dashboard shows one row per explicit broker, ignores multi-person state, hides the ~490
generic brokers and has no history.
**Shape.** A run-history tab (from the run logs: date, mode, counts per status, per person), per-person
status in the broker table, generic-broker totals in the summary, and a "solve these CAPTCHAs" call to
action linking to `aidr captchas`.

## Later

- Fill and submit inside one `<form>` for the explicit brokers too (the generic runner already does).
- Match relay-forwarded confirmation mail: SimpleLogin rewrites `From` to a reverse alias, so those
  confirmations are not clicked today.
- Live IMAP fetching of confirmation mail (today: a local `.eml` folder). Needs an IMAP client dependency
  and its own review of the SSRF and sender checks.
- Windows in CI (PR #18 made the suite pass there).
- State backend with schema versions (SQLite/WAL), which also removes the full-file rewrite per result.
- A per-run CapSolver spend cap.
- Masked `From` address for opt-out emails when a relay is configured.
- Evidence-backed removal: `--verify` proves a listing existed before counting its absence as a removal.
